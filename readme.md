# Graph-Feature AML Detection — IBM HI-Small

> A single transaction rarely looks illicit. A *subgraph* of transactions often does.

Anti-money-laundering transaction monitoring on the IBM synthetic AML dataset. The project
tests one claim: that **graph-derived features** — fan-out, fan-in, cycles, layering,
community structure — detect laundering that a conventional row-wise tabular model misses,
and it tests it with a controlled ablation rather than asserting it.

The methodological core is not the model. It is the **temporal contract**: structural
features are computed on lagged daily graph snapshots so that no transaction can ever
contribute to its own features, and the train/val/test split is purged so that no laundering
ring appears on both sides of a boundary.

Full design: [architecture.md](architecture.md). Working agreement: [project_info.md](project_info.md).

---

## Dataset

**IBM Transactions for Anti Money Laundering (AML)** — synthetic, generated by IBM Research
via a multi-agent virtual-world simulation of banks, individuals and companies.

- **Link:** <https://www.kaggle.com/datasets/ealtman2019/ibm-transactions-for-anti-money-laundering-aml>
- **Licence:** **CDLA-Sharing-1.0** (Community Data License Agreement — Sharing, v1.0)
- **Variant used:** `HI-Small` only. The full dataset is ~41.6 GB across all variants; the
  Medium and Large variants are explicitly out of scope.

Data is **not committed to this repository** — `data/` is gitignored. It is ~510 MB,
licensed, and fully regenerable from Kaggle. The commands below are the only recovery path,
so treat them as part of the setup rather than as an appendix.

## Setup

### 1. Interpreter

**Python 3.12.x is required, not merely recommended.** Three pinned dependencies
(`numpy`, `shap`, `python-igraph`) publish no wheels for 3.13+, so the environment cannot be
reconstructed on a newer interpreter. Built and verified on **3.12.14**.

Using [uv](https://docs.astral.sh/uv/) (recommended — it can fetch the interpreter too):

```bash
uv python install 3.12
uv venv --python 3.12
uv pip install -r requirements.txt
uv pip install -e .
```

Or with stock tooling, assuming `python` is already 3.12:

```bash
python -m venv .venv
.venv/Scripts/activate        # Windows;  source .venv/bin/activate on Linux/macOS
pip install -r requirements.txt
pip install -e .
```

Verify:

```bash
pytest -q                     # expect: 91 passed
```

### 2. Dataset

Requires a Kaggle account and an API token (`kaggle.json` → `~/.kaggle/kaggle.json`; it is
gitignored here). Then:

```bash
mkdir -p data/raw
kaggle datasets download -d ealtman2019/ibm-transactions-for-anti-money-laundering-aml \
    -f HI-Small_Trans.csv    -p data/raw --unzip
kaggle datasets download -d ealtman2019/ibm-transactions-for-anti-money-laundering-aml \
    -f HI-Small_Patterns.txt -p data/raw --unzip
```

Optional — only needed if experiment E5 shows the account reference file earns its place:

```bash
kaggle datasets download -d ealtman2019/ibm-transactions-for-anti-money-laundering-aml \
    -f HI-Small_accounts.csv -p data/raw --unzip
```

Expected afterwards:

```
data/raw/HI-Small_Trans.csv        ~475 MB, 5,078,345 rows
data/raw/HI-Small_Patterns.txt     370 laundering-attempt blocks
```

The ingest stage asserts the row count, so a partial or wrong-variant download fails loudly
rather than producing quietly wrong numbers.

## Reproducing the results

Each stage is idempotent and cached by a hash of the config subset that produced it, so
re-running a stage with unchanged config is a no-op. Run in order:

```bash
python scripts/00_ingest.py                    # raw -> canonical parquet        (~30 s)
python scripts/01_graph.py                     # 10 daily snapshot graphs        (~30 s)
python scripts/01_graph.py --verify-backend    # igraph vs networkx checkpoint
python scripts/02_features.py                  # feature matrix + manifest
python scripts/03_train.py                     # model rungs + OOF predictions
python scripts/04_evaluate.py                  # metrics + report figures
python scripts/05_walkforward.py               # rolling-origin decay study
```

The headline ablation is two runs of the same code path against different configs:

```bash
python scripts/02_features.py --experiment ablation_tabular   # arm A: tabular only
python scripts/02_features.py --experiment ablation_graph     # arm B: tabular + graph
```

All randomness flows from a single `seed` in [config/default.yaml](config/default.yaml).

## Layout

```
config/          single source of truth; experiments/ holds the ablation config diffs
src/aml/         all logic — ingest, graph, features, models, evaluate, viz
scripts/         thin CLI wrappers, one per pipeline stage
notebooks/       narrative only; nothing important is defined here
tests/           guards on the contracts where a silent failure would invalidate a result
report/          methodology and results write-up
data/            gitignored — see Dataset above
artifacts/       gitignored — regenerable outputs, keyed by config hash
```

`src/aml/` holds the truth; `scripts/` and `notebooks/` only orchestrate and narrate. That
separation is what makes "reproduce our results" a real claim rather than a hopeful one.

## Scope

Deliberately **not** built: live or streaming inference, a deployed API, graph neural
networks, exact betweenness centrality, the Medium/Large dataset variants, or more than 3–4
base models. Production architecture is documented in `architecture.md` §14 as design — it
is not implemented, and the report says so.
